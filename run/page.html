EVM: EEST benchmark blocks

Eight copies of one 150M-gas block per file, run one after another through each client's own blockchain-test tool (geth and erigon evm blocktest, revme blockchaintest, nethtest -b, evmone test, gevm RunBlockchainTestFile), one block per process. Mgas/s = gas / (wall time of the file − wall time of the same file with no blocks), best of 3. Every client parses the fixture, executes the block and checks the state root, so the number is comparable across clients. gevm is the exception: it has no trie, computes no state root and checks the post-state account by account, from geth's dump of the same block; read its column as an upper bound. Grey = the no-block twin is more than 30% of the run or the net time is under 100 ms: setup-dominated or too short for a wall clock. nethtest's dotnet start-up is ~3 s, so nethermind runs the file and the twin second in one process after a pass of the file: start-up and JIT warm-up cancel, nethermind is measured warm, and only the 100 ms floor greys its cells. A client with fewer than half of its blocks valid is left out of the hero. The precompile tests repeat one input, and geth and neth serve repeated precompile calls from a result cache, so that group compares caches, not precompiles; the hero uses instruction and scenario only. Fixtures: EEST tests-benchmark@v0.0.9, 150M variant.

RPC workloads

Request corpora anyone can replay against their own mainnet node: workloads/, one directory per workload with the JSON-RPC bodies, the pinned block and the rate ladder. Open loop at each rate, 20 s; rps below the rate means the node is at capacity; latency in ms; err = failed requests; a node that answers errors to a workload is skipped. Numbers from different machines compare on latency at equal rate and on the knee, not on peak rps.
